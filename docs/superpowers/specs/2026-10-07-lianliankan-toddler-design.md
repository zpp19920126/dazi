# 幼儿连连看（粉色童话风）— 可交互 HTML 原型设计

- 日期：2026-10-07
- 状态：已实现并验收（浏览器走查完成；真机+真人待家长执行，见 prototype/README.md）
- 交付物：`prototype/lianliankan-prototype.html`（单文件可交互原型）+ 本设计文档
- 目标用户：3 岁女孩（家长代持手机/平板，孩子直接触屏操作）

## 1. 目标与非目标

**目标**

1. 做出一个 3 岁孩子能独立上手、玩得开心、获得正反馈的手机连连看可交互原型。
2. 验证"分阶递进"玩法（自由配对 → 单转弯 → 标准规则）对幼儿是否成立。
3. 原型代码分模块组织，玩法验证后可低成本迁入 Capacitor 打包 APK。

**非目标（本次不做）**

- 不做正式 APK（列为后期演进任务）。
- 不做背景音乐、排行榜、广告、内购、账号。
- 不做 E2E 自动化测试；不做 React/构建工具链接入。
- 图案不做定制美术（原型用 Emoji，APK 阶段再替换 SVG）。

## 2. 核心设计原则

面向幼儿的三条铁律，所有细节服从此原则：

1. **无失败态**：没有计时、没有 ✗、没有红色警告、没有"游戏结束"。配对失败只是"再找一个试试"。
2. **永远可继续**：任何局面都保证存在可消除的配对；检测到死局自动洗牌。
3. **反馈即时且正向**：每次有效操作在 300ms 内有视觉+听觉回应；完成每一对都有鼓励。

## 3. 玩法与关卡递进

共 9 关，三阶段。规则由 `maxTurns` 参数统一表达（free 档不校验路径）。

| 阶段 | 关卡 | 棋盘 | 配对数 | 图案种类 | 规则 |
|---|---|---|---|---|---|
| 配对启蒙 | 1-3 | 3×4 → 4×4 | 6 → 8 对 | ≤6 种 | 自由配对：点两张相同图案即消除，不校验路径 |
| 简单路径 | 4-6 | 4×4 → 4×5 | 8 → 10 对 | ≤8 种 | 仅允许 0 转弯直线与 1 转弯路径（`maxTurns=1`）；死局自动洗牌 |
| 小小挑战者 | 7-9 | 4×6 → 5×6 | 12 → 15 对 | ≤10 种 | 标准 ≤2 转弯（`maxTurns=2`）；每关 1 次免费提示 |

补充规则：

- 每关图案从该关图案池中随机取，同图案不要求视觉差异（同一 Emoji 重复出现即是配对目标，数量恒为偶数）。
- 新规则引入关（第 4、7 关）进入游戏时用语音+演示动画讲解一次，可跳过。
- 通关 9 关后重进显示"你已经是个连连看小高手啦!"，第 1 关起可重复玩（图案随机重排）。
- 棋盘生成保证可解：先按规则放好若干条合法配对路径再生成摆法；摆法不可解则重新生成（engine 内部自校验）。

## 4. 页面结构与屏幕流

竖屏基准 375×812，5 个界面。屏幕流：

```
[① 开场页] ──点大按钮──▶ [② 关卡地图] ──点当前关──▶ [③ 游戏主界面]
                                                          │ 全部消除
                                                          ▼
                                               [④ 过关庆祝页] ──3s自动/点击──▶ 下一关或地图
[⑤ 家长设置] ◀── 长按开场页Logo 3s（隐藏入口，孩子碰不到）
```

### ① 开场页

```
┌───────────────────┐
│      (飘云背景)     │
│    ◤独角兽Logo◢    │ ← 长按3s=家长设置入口
│                   │
│   ┌───────────┐   │
│   │           │   │
│   │  开始玩!   │   │ ← 大圆按钮，占屏宽40%
│   │           │   │

│                   │
└───────────────────┘
```

仅一个按钮。进入即语音播报"我们来玩连连看吧!"。无菜单、无文字链接。

### ② 关卡地图

```
┌───────────────────┐
│ ← 返回     ★ 4/9   │
│              (9)○  │ 城堡图标·未解锁半透明
│          (8)○      │
│       (7)○         │
│    (6)○  ╱         │
│  (5)◉ ╱  ← 当前关   │ ← 跳动+发光
│      ╱  (4)●       │ ← 已通过：亮色+星标
│   (3)●             │
```

9 个圆形节点沿一条弯曲粉色小路排布（之字形，自底向上）。已通关卡亮+显示星星；当前关呼吸动画；未解锁半透明但可见（呈现目标感）。不依赖数字阅读，靠位置顺序。

### ③ 游戏主界面

```
┌───────────────────┐
│ ←        🏠3/9  ⭐ │ 顶栏仅返回箭头+关卡星星进度
│ ┌───┐┌───┐┌───┐┌───┐│
│ │ 🦄 ││ 🐰 ││ 🍓 ││ ⭐ ││
│ └───┘└───┘└───┘└───┘│  卡片=白底粉边圆角大块
│ ┌───┐┌─●─┐┌───┐┌───┐│   ●=选中：放大15%+金边发光
│ │ 🌈 ││ 🦄 ││ 🎀 ││ 🧁 ││
│ └───┘└───┘└───┘└───┘│
│  ……（网格随关卡变化） │
│            (💡提示)  │ ← 第7关起出现，每关1次
└───────────────────┘
```

- 卡片尺寸：3×4 时单格约 25% 屏宽；任何关卡不小于 15% 屏宽，保证幼儿粗指点准。
- 禁用双击缩放、双指缩放、长按选中文字/图片（`touch-action`、`user-select` 处理）。
- 空白区域无交互；除返回箭头外顶部无按钮。

## 5. 交互与反馈明细

| 场景 | 视觉 | 听觉 | 其他 |
|---|---|---|---|
| 选中卡片 | 放大 15% + 金色描边发光 | "叮"轻音（合成） | — |
| 配对成功 | 沿消除路径画流动彩虹线（约 400ms）→ 两卡弹跳两下化星星粒子消散 | 轮换鼓励语："真棒!"/"就是这样!"/"好厉害呀!" | 成功震动 30ms（支持则用） |
| 配对失败（异图案或路径不通） | 两卡轻轻摇头（左右小摆）后弹回；**无 ✗、无红色** | 中性泡泡音 + "再找一个试试" | — |
| 点提示灯（7-9 关） | 自动选中最慢 3 秒的一对候选呼吸闪烁 | 柔和风铃音 | 每关 1 次，用后灯变暗，无批评语 |
| 死局（4-6 关规则下可能） | 全卡"飞起转一圈"重排 | "老师帮你重新摆好啦，继续!" | 自动触发，无需孩子操作 |
| 进入新规则关（4/7） | 演示动画（高亮两卡+画出路径） | 一句规则口语解释 | 3s 后自动开始，或点击跳过 |

## 7. 技术架构

单文件 `prototype/lianliankan-prototype.html`，内部分 5 个模块，依赖自上而下，为迁入 APK 预留边界：

```
LEVELS（配置数据，纯JSON）
   ▼
engine（纯函数，无DOM/无音频）
   ├─ 棋盘生成（保证可解）        依赖: LEVELS
   ├─ 选中状态机                  对外: select(cell) → events
   ├─ 路径校验 BFS(maxTurns)      对外: canLink(a,b) → path|null
   └─ 死局检测                    对外: hasAvailablePair(board)
   ▼
view（DOM网格 + SVG连线层 + CSS动画）  只消费 engine 事件
audio（Web Audio 合成音效 + speechSynthesis 中文鼓励语音）
store（localStorage：通过关卡、开关设置、每关提示次数）
```

关键决策：

- **路径校验**：BFS 带转弯数状态（`cell, dir, turns`），`maxTurns ∈ {0,1,2}` 参数化，同一算法服务三个阶段；自由配对档不调校验直接判图案相同。棋盘外缘允许绕行（虚拟外圈）。
- **可解生成**：生成布局后运行死局检测，不可解则重生成（上限 50 次，超过则降级为自由配对档布局并静默）。
- **语音**：`speechSynthesis` `zh-CN`，rate 0.9、pitch 1.3；句子为固定小集合。不可用→仅音效。
- **音频初始化**：首次用户触摸后创建 AudioContext（浏览器自动播放策略），失败静默。

## 8. 错误处理哲学

任何异常不得白屏、不得弹框、不得中断游戏：

| 故障 | 行为 |
|---|---|
| engine 生成 50 次仍可解失败 | 降级自由配对布局，玩家无感知 |
| speechSynthesis / AudioContext 不可用 | 只播可用部分；全不可用则纯视觉 |
| localStorage 不可用（无痕 Safari） | 进度降级为内存态，本局有效 |
| vibrate 不支持 | 跳过震动 |
| JS 运行时异常 | 捕获后回当前关卡初始盘面，不出现报错界面 |

## 9. 测试与验证

- **engine 单元测试**（`node --test`）：将 engine 段落提取为临时 `.mjs` 后运行——覆盖 `canLink` 0/1/2 转弯用例、死局检测、棋盘生成必可解性质（每关型跑 100 次生成）。
- **手工验收清单**（浏览器）：逐关通关 1-9；失败反馈无否定元素；死局自动洗牌触发；提示每关仅一次；长按 Logo 进家长页；无痕模式不崩；iOS Safari 与 Android Chrome 各过一遍。
- **真人验证**：交付后由家长给 3 岁孩子试玩 10 分钟，观察：能否自发点两下相同图案、失败后是否继续、是否要求再来一局。此反馈决定是否进入 APK 阶段。

## 10. 成功标准

1. 孩子在无家长手把手教学下 ≤2 分钟开始主动配对。
2. 全程无一次因"消不掉/不理解规则"而卡住弃玩（家长观察口径）。
3. 9 关全部可通关；无死局、无白屏、无报错弹窗。
4. 单文件、零网络依赖，断网可玩。

## 11. 演进路径（后续计划，非本次实现）

## 12. 决策记录

- 交付形式：可交互 HTML 原型（用户选定，弃静态线框）。
- 玩法：分阶递进（用户选定，弃纯自由配对与纯经典规则）。
- 主题：粉色童话（用户选定）。
- 声音：音效+鼓励语音，无 BGM（用户选定）。
- 路线：单文件原型先行，Capacitor 出 APK 列入演进（用户确认 APK 需求后选定）。
